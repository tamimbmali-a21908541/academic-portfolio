# Software Engineering

> Laboratory work across the development lifecycle — Agile requirements, UML modelling, UX wireframing, and software architecture with DevOps.

**Grade:** 13/20 · **ECTS:** 5 · **Year:** 3 · **Institution:** Universidade Lusófona

---

## Overview

A sequence of labs covering how software gets specified, modelled, designed, and delivered — the practices that surround writing code.

## Lab work

**Agile**
- **User Stories** — expressing requirements from the user's perspective
- **Acceptance Criteria** — making "done" objective and verifiable

**UML modelling**
- **Entity-Relationship diagrams** — data structure
- **Class diagrams** — static system structure and relationships
- **Sequence diagrams** — interaction and message flow over time

**UX/UI**
- Wireframing — layout and information architecture before visual design

**Architecture and DevOps**
- Software architecture patterns and their trade-offs
- DevOps practices for build and delivery

## Key takeaways

- **Acceptance criteria are where a user story becomes buildable.** The story captures intent; the criteria remove the ambiguity that would otherwise be resolved by guessing.
- **The three UML diagram types answer different questions** — class diagrams show what exists, sequence diagrams show what happens, ER diagrams show what is stored. Reaching for the wrong one produces a diagram nobody reads.
- **Wireframing separates layout decisions from visual ones,** so each gets discussed on its own terms.
- **Architecture is the set of decisions that are expensive to reverse,** which is what makes it worth deliberating over up front.
